# Windows system telemetry (2.3-09 slice)

The 2.3-09 slice owns battery, power, CPU, memory, storage, and network observations in the Windows Agent. `GetSystemPowerStatus` supplies charge, AC/battery state, charging flag, and the Windows-reported remaining lifetime when available. `GetSystemTimes` supplies a bounded system-wide CPU sample, while `GlobalMemoryStatusEx` supplies total, available, and derived used physical memory. `DriveInfo` supplies the actual system volume's total and available bytes, while `NetworkInterface` supplies usable non-loopback, non-tunnel interfaces, IPv4 addresses, types, and link speeds when available. Unsupported or failed values remain nullable; no runtime, CPU, storage, or Internet reachability value is inferred from unrelated fields.

V3.0 extends each connected wireless-interface observation with nullable `ssid`. The Agent queries the native Windows WLAN API for the matching connected interface and reads the current connection's length-bounded SSID bytes. Invalid UTF-8, empty or whitespace-only values, control characters, over-length values, access denial, unavailable WLAN service, and all native-query failures produce `null` without failing the remaining system observation. The Agent does not send BSSID or MAC address in this contract. An older Agent that omits `ssid` remains compatible with the Dashboard.

The Agent exposes the observation through `FieldOps.SystemTelemetry.v1`; Express reads that local pipe at `/api/system`, and the Dashboard treats it as authoritative. Browser Battery API data is not used as a production fallback when native telemetry is unavailable. Network availability means at least one qualifying local interface is operational; it does not claim Internet reachability.

The normal network display uses the SSID for connected Wi-Fi, `Wi-Fi connected (name unavailable)` when the SSID is absent, `Ethernet connected` or `Cellular connected` for those interface types, `Disconnected` when no qualifying interface is up, and `Network telemetry unavailable` when the observation is missing. Interface name, description, type, IPv4 address, and link speed remain diagnostic data rather than the normal header label.
