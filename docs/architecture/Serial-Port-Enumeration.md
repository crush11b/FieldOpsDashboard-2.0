# Serial-port enumeration (2.3-07A)

The Local Agent is authoritative and exposes the authenticated, read-only `GET /api/v1/serial-ports` contract. It uses `System.IO.Ports.SerialPort.GetPortNames()` for the currently exposed COM-name list and a managed WMI provider for best-effort metadata enrichment. Metadata is merged onto that authoritative list; missing or malformed values remain null rather than fabricated. Enumeration never opens a port, probes baud rates, changes configuration, or sends bytes.

The Agent also owns the dedicated read-only Named Pipe `FieldOps.SerialInventory.v1`. Its ACL authorizes only LocalService, local Administrators, and the configured `FieldOps Operators` SID. The dashboard backend connects under the current Windows operator identity, sends only `GetSerialPortInventory`, validates bounded framed JSON, and proxies the response to the browser at `/api/serial-ports`. No bearer credential crosses into Node or the browser. Agent unavailable, access denied, timeout, malformed response, unavailable status, and error status remain distinct. The dashboard presents a small Serial ports panel with count, COM names, available metadata, honest unavailable/error states, last refresh time, and a manual Refresh action. It refreshes every 30 seconds. Zero ports is a successful empty result.

This first slice does not implement GNSS/NMEA, device selection, arrival events, or hardware validation. The ToughBook procedure is: record baseline; plug in a known USB serial device; confirm the new COM port appears; unplug it; confirm it disappears; compare friendly name and identifiers with Device Manager; verify no device is opened or disrupted and the dashboard remains responsive. Use any known USB-to-serial adapter or field radio interface available on the test machine; do not assume a particular device is attached.
